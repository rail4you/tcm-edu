# tcm-edu — Traditional Chinese Medicine Education

A full-stack skeleton for a **Traditional Chinese Medicine (TCM) Education**
platform, built with **Phoenix 1.8** + **Ash** on the backend and **Next.js**
on the frontend, glued together by **AshTypescript**'s generated RPC client.

The project shows how to ship a Phoenix + Ash backend with a fully-static
Next.js SPA, with a real RPC endpoint, a real database, AshAuthentication
with RBAC, AshStorage file uploads, Jido AI agents, and Oban background
jobs. Authentication is wired up — see the [seeded credentials](#seeded-users)
or create your own account from the UI.

> The technical architecture (Phoenix + Ash + AshTypescript + Postgres +
> Jido + Oban + AshStorage) is intentionally preserved from the original
> scaffold. Subsequent refactors will adapt the resources and copy
> to the TCM Education domain (e.g. `Todo → Note`, `Post → Course`,
> `Chat → TcmTutor`).

## What's in the box

```
.
├── config/                     # Phoenix + AshTypescript config
├── lib/tcm_edu/                # Domain modules (Accounts, Todo, Post, Chat, Storage, Agents)
├── lib/tcm_edu_web/            # Endpoint, router, RPC + SPA controllers
├── priv/
│   ├── repo/migrations/        # auto-generated by ash_postgres
│   └── app/                    # Next.js static export target (build artefact)
└── frontend/                   # Next.js 16 + Tailwind 4 + TypeScript 5
    └── lib/generated/          # mix ash_typescript.codegen output
```

The generated TypeScript lives at
`frontend/lib/generated/{ash_rpc,ash_types,ash_zod}.ts` and is committed
to the repo so the frontend can type-check without first running
`mix`. Re-run `mix ash_typescript.codegen` whenever you change a
resource or RPC action.

## Prerequisites

| Tool    | Version (tested) | Where used |
|---------|------------------|------------|
| Elixir  | 1.18 / OTP 27    | Phoenix    |
| Node    | ≥ 22             | Next.js    |
| pnpm    | ≥ 10             | Next.js    |
| Postgres | 13+            | AshPostgres |

The default DB config points at `localhost:5433` with `postgres/postgres`
credentials. Override with the standard `PG*` env vars or `DATABASE_URL`
(see `config/{dev,runtime}.exs`).

## First-time setup

```bash
mix setup                                    # get deps + create + migrate DB + seed RBAC
mix ash_typescript.codegen                   # write TypeScript client (idempotent)
pnpm --dir frontend-monorepo install         # install all workspace deps
```

## Development

Frontend lives in `frontend-monorepo/` (pnpm workspaces: student / admin /
teacher apps + shared `rpc-client` package). Run each server in a separate
terminal (or use `./bin/herdr-services.sh` for the Phoenix pane):

```bash
# Terminal 1 — Phoenix (RPC + DB)
mix phx.server                               # http://localhost:4011

# Terminal 2 — Student app (HMR)
pnpm --dir frontend-monorepo --filter @tcm-edu/student dev   # http://localhost:3001

# Terminal 3 — Admin console (HMR)
pnpm --dir frontend-monorepo --filter @tcm-edu/admin dev     # http://localhost:3002
```

Open `http://localhost:3001` (student) or `http://localhost:3002/login`
(admin). RPC calls hit `/api/rpc/*` on each app's own port, which Next.js
transparently rewrites to Phoenix on port 4011 (see each app's
`next.config.mjs`). CORS is wired up in the `:api` pipeline.

## Production — single process

Build the static frontend into `priv/app/` and let Phoenix serve
everything:

```bash
# NOTE: production static-export wiring is being reworked for the monorepo
# (Phase 11). For now, build the student app:
pnpm --dir frontend-monorepo --filter @tcm-edu/student build   # → apps/student/out/
MIX_ENV=prod mix phx.server                  # http://localhost:4011
```

Visit `http://localhost:4011/app/`. `Plug.Static` (configured in
`TcmEduWeb.Endpoint`) serves the static files; `FallbackController`
returns `index.html` for unmatched paths so Next.js client-side routing
works.

## Resources

The app currently ships with the architecture demo's resources intact:
`Todo`, `Post`, `ChatSession` / `ChatMessage` / `ChatTask`, and the
`Accounts` domain (User, Role, Permission, RBAC join tables) with
`AshAuthentication` (password strategy + bearer tokens).

`lib/tcm_edu/post.ex` demonstrates `AshStorage` file attachments
(`has_one_attached :cover_image`, `has_many_attached :attachments` with
analysers and a video thumbnail variant).

`lib/tcm_edu/chat_domain.ex` exposes the chat sessions, messages, and
background tasks surfaced by the AI agent runtime in
`lib/tcm_edu/agents/`.

## Re-generating the RPC client

```bash
mix ash_typescript.codegen                   # write ts files
mix ash_typescript.codegen --check           # fail in CI if out of date
```

Outputs:

- `frontend/lib/generated/ash_rpc.ts`     — fetch functions and result types
- `frontend/lib/generated/ash_types.ts`   — resource schemas, filters, sorts
- `frontend/lib/generated/ash_zod.ts`     — Zod schemas for runtime validation

The endpoint URLs (`/api/rpc/run`, `/api/rpc/validate`) are baked into
`ash_rpc.ts` at codegen time. Change them via
`config :ash_typescript, :run_endpoint` if you re-route.

## Database tips

```bash
mix ecto.migrate                            # apply pending migrations
mix ecto.rollback                           # roll back the last one
mix ash.codegen --dev                       # scaffold + apply a dev migration
mix ash.codegen add_whatever                # scaffold a named migration
```

Migrations live under `priv/repo/migrations/` and
`priv/resource_snapshots/` (the latter is how AshPostgres knows your
resource shape).

## Verifying the end-to-end flow

```bash
mix compile                                 # 0 warnings
mix ecto.migrate                            # DB up to date
mix ash_typescript.codegen                  # 3 ts files emitted (packages/rpc-client/src/)
pnpm --dir frontend-monorepo -r typecheck # 0 ts errors
pnpm --dir frontend-monorepo --filter @tcm-edu/student build  # writes apps/student/out/

# smoke test
curl -s -X POST http://localhost:4011/api/rpc/run \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <token>' \
  -d '{"action":"list_todos","fields":["id","title","completed"]}'
# => {"data":[],"success":true}
```

## Notes & caveats

- **`force_ssl` is intentionally disabled in `config/prod.exs`.** That's
  so `MIX_ENV=prod mix phx.server` works over plain HTTP for local
  verification. Re-enable it (and supply `SECRET_KEY_BASE`,
  `DATABASE_URL`, etc.) when you ship somewhere real.
- **`picosat_elixir` is included.** Ash's policy authorizer needs a SAT
  solver — `picosat_elixir` is a fast NIF binding. Swap for
  `simple_sat` if you want a pure-Elixir fallback.
- **`priv/app/` is build output.** It is regenerated on every
  `pnpm build`. `.gitkeep` is the only thing tracked there in git.
