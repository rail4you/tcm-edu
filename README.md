# tcm-edu — Traditional Chinese Medicine Education

A full-stack **Traditional Chinese Medicine (TCM) Education** platform,
built with **Phoenix 1.8** + **Ash** on the backend, served entirely via
**LiveView + daisyUI** (no separate frontend SPA). The system includes
AshAuthentication with RBAC, AshStorage file uploads, Jido AI agents, and
Oban background jobs.

## What's in the box

```
.
├── config/                     # Phoenix + Ash config
├── lib/tcm_edu/                # Domain modules (Accounts, Courses, Quiz, Chat, AI, Storage, …)
├── lib/tcm_edu_web/            # Endpoint, router, LiveView pages, controllers
├── priv/
│   ├── repo/migrations/        # auto-generated by ash_postgres (public schema)
│   └── repo/tenant_migrations/ # auto-generated tenant-schema migrations
└── assets/                     # Tailwind v4 + daisyUI (esbuild pipeline)
```

All UI is rendered server-side by LiveView:

- Student portal — `/` (home), `/courses`, `/learn`, `/my-learning`, `/posts`, `/chat`, `/notifications`
- Teacher portal — `/teacher` (dashboard), `/courses`, `/quiz`, `/ai/*` (备课 / 配图 / 出题 / 问答)
- Admin portal — `/admin` (users / tenants / AI dashboard / AI keys)

AI features (lesson plans, quiz generation, medical images, chat) are powered
by **Jido agents**; long-running generation runs in **Oban** background
workers so the page can be left mid-task without interrupting the work.

## Prerequisites

| Tool     | Version (tested) | Where used     |
|----------|------------------|----------------|
| Elixir   | 1.18 / OTP 27    | Phoenix / Ash  |
| Postgres | 13+              | AshPostgres    |
| Node     | ≥ 22             | Phoenix assets (esbuild) |

The default DB config points at `localhost:5433` with `postgres/postgres`
credentials. Override with the standard `PG*` env vars or `DATABASE_URL`
(see `config/{dev,runtime}.exs`).

## First-time setup

```bash
mix setup                                    # get deps + create + migrate DB + seed
```

## Development

```bash
mix phx.server                               # http://localhost:4000
./restart.sh restart                         # convenience wrapper (kills & restarts Phoenix)
```

Open `http://localhost:4000/` and log in through `/login` (student /
teacher / admin tabs).

生产部署（构建镜像 / 远程部署 / 迁移 / nginx 反代）见 **[docs/deployment.md](docs/deployment.md)**。

### Seeded users

See `lib/mix/tasks/tcm_edu.seed_super_admin.ex` and the tenant seed for
the default super admin credentials.

## Migrations (AshPostgres + tenant schemas)

After changing resources, generate migrations with:

```bash
mix ash.codegen add_short_snake_name        # named migration (final)
mix ash.codegen --dev                       # during iteration
```

Apply with `mix tcm_edu.migrate` (public + default tenant + all tenant
schemas) or `mix tcm_edu.migrate --tenants` (tenant schemas only).

## Background jobs (Oban)

Oban uses the same Postgres database as Ash. Insert jobs via
`Worker.new(args) |> Oban.insert()`. Long-running AI tasks broadcast
PubSub events (`quiz_jobs:<tenant>` etc.) that LiveView surfaces as live
banners.

## Database tips

```bash
mix ecto.migrate                            # apply pending migrations
mix ecto.rollback                           # roll back the last one
mix ash.codegen --dev                       # scaffold + apply a dev migration
mix ash.codegen add_whatever                # scaffold a named migration
```

Migrations live under `priv/repo/migrations/` and
`priv/repo/tenant_migrations/` (the latter is how tenant schemas are kept
in sync).

## Verifying the end-to-end flow


## Notes & caveats

- **`force_ssl` is intentionally disabled in `config/prod.exs`.** That's
  so `MIX_ENV=prod mix phx.server` works over plain HTTP for local
  verification. Re-enable it (and supply `SECRET_KEY_BASE`,
  `DATABASE_URL`, etc.) when you ship somewhere real.
- **`picosat_elixir` is included.** Ash's policy authorizer needs a SAT
  solver — `picosat_elixir` is a fast NIF binding. Swap for
  `simple_sat` if you want a pure-Elixir fallback.
- **AI keys come from env vars** (`QWEN_API_KEY` / `DASHSCOPE_API_KEY`)
  or the `ApiKeyConfig` table (super admin can set them at runtime).
  Never commit keys.
